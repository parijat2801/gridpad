# Theme Tweak Panel

Goal: live-edit fonts, sizes, line heights, cell-size multipliers, and colors from a toggleable popover so visual polish iterations don't require code edits or rebuilds.

This is v3 of the plan. v2 folded Gemini's first review (useSyncExternalStore, mutable-object pattern, Tauri v2 capability declaration, document.fonts.load await, CSS-var routing). v3 folds Gemini's review-of-v2 (2026-05-07): drops the canvas backing-buffer task (the existing code already handles content growth via the DOM spacer pattern, not by resizing the canvas — canvas is sized to viewport×DPR), splits `updateTheme` into sync-notify-then-async-side-effects to prevent controlled-input snap-back during slider drags, adds `preparedRef` cache rebuild to the reflow bucket (cache entries are computed against a specific prose font and must be regenerated when prose font/size changes), and corrects `proseLineHeight` default from 28 to 22 to match `textFont.ts:14`.

## Plan

1. **All knobs live in one mutable object** at `src/theme.ts`: `export const theme: Theme = { ... }`. Call sites read `theme.wireframeFontSize` directly — no getter functions, no function-call overhead in the paint loop. The reason this works (where `import const FONT_SIZE` doesn't) is the *property* read happens at call time; ES module imports of objects are live bindings to the same reference, so mutating fields propagates everywhere. The `Theme` shape: `proseFontFamily`, `proseFontSize`, `proseLineHeight`, `proseColor`, `wireframeFontFamily` (monospace-only — picker enumerates `Menlo`/`Monaco`/`Courier New`/`SF Mono`/`JetBrains Mono`), `wireframeFontSize`, `wireframeColor`, `charWidthMultiplier`, `charHeightMultiplier`, `bgColor`, `selectionColor`, `gridBorderColor`. **`updateTheme(patch: Partial<Theme>)` ordering is critical** — it must (a) `Object.assign(theme, patch)` synchronously, (b) bump a snapshot version (so `getSnapshot` returns a fresh frozen copy), (c) **synchronously notify subscribers** (so React's `useSyncExternalStore` re-renders controlled inputs immediately and the slider thumb tracks the drag), then (d) classify the patch and kick off the *async* side-effect (font-load + measure + reflow + paint, or paint-only, or css-var write). Subscriber notification must NOT wait for the side-effect — that's the bug that causes slider thumbs to snap back during a drag. Steps a–c are sync; step d is fire-and-forget.

2. **Cell-size derivation pulls multipliers from theme.** Today `grid.ts:28` hardcodes `(ascent+descent) * 1.4` — that 1.4 *is* the cell-height multiplier, just buried as a magic number. `measureCellSize` reads `theme.wireframeFontSize`/`theme.wireframeFontFamily`/`theme.charWidthMultiplier`/`theme.charHeightMultiplier`; computes `_charWidth = measuredWidth * widthMul`, `_charHeight = (ascent+descent) * heightMul`. Same fallback clamps stay (the 4–40 sanity check guards against pathological multipliers, not just measurement bugs).

3. **`grid.ts` and `textFont.ts` constants migrate to theme reads.** `FONT_SIZE`, `FONT_FAMILY`, `FG_COLOR`, `PROSE_FONT_MEASURE`, `PROSE_FONT_RENDER`, `PROSE_LINE_HEIGHT` get deleted; call sites (`frameRenderer.ts:5,105,106,136,137`, `DemoV2.tsx:32,33,35,421,443,465,471,472,494,553,1029,1519,1527,1534`, `preparedCache.ts:2,12,26,41,45,61`) replace them with `theme.wireframeFontSize` etc., or with helper expressions (`getProseFontMeasure() = \`${theme.proseFontSize}px ${theme.proseFontFamily}\`` — these stay as functions because they compose; called at paint/measure time, not module load). `DemoV2.tsx:35`'s `const FONT = \`${FONT_SIZE}px ${FONT_FAMILY}\`` becomes a per-paint local: `const font = \`${theme.wireframeFontSize}px ${theme.wireframeFontFamily}\`` inside the paint scope.

4. **Re-measure on font changes, repaint on color changes, CSS-vars for DOM colors.** `updateTheme` classifies the patch into three buckets: `'reflow'` (touches `wireframeFontFamily`/`wireframeFontSize`/`charWidthMultiplier`/`charHeightMultiplier`/`proseFontFamily`/`proseFontSize`/`proseLineHeight` — see reflow steps below), `'paint'` (touches `proseColor`/`wireframeColor` — canvas-side colors, just `paint()`), `'css-vars-only'` (touches `bgColor`/`selectionColor`/`gridBorderColor` — DOM-side colors, write CSS variables on `:root`, no React or canvas work). The classifier lives in `theme.ts` but the reflow handler lives in `DemoV2.tsx` (it needs `stateRef`/`preparedRef`/`framesRef` access). The reflow path executes IN ORDER: (i) `await document.fonts.load(...)` for the new font strings, (ii) `await measureCellSize()` (theme-aware — reads multipliers and font fields), (iii) **rebuild `preparedRef.current = buildPreparedCache(proseRef.current)`** because cache entries hold word-wrap measurements computed against the *old* prose font; skipping this step makes text wrap at stale boundaries on prose font changes, (iv) `doLayout()` to rerun reflow with the new metrics, (v) `paint()`. Pretext does not use color in measurement — confirmed in review — so color changes never reflow. Patches that span multiple buckets take the strongest action (reflow > paint > css-vars).

5. **DOM colors route through CSS variables, not React props.** On `theme.ts` module load, set `document.documentElement.style.setProperty('--theme-bg', theme.bgColor)` etc. for `bgColor`/`selectionColor`/`gridBorderColor`/`proseColor`/`wireframeColor`. The toolbar div in `DemoV2.tsx:1517`, the divider at `:1523`, and active-button background at `:1519`/`:1527`/`:1534` switch from inline hex to `var(--theme-selection)` etc. CSS-var-only updates skip canvas repaint entirely — the browser handles them. Canvas-side colors (`proseColor`/`wireframeColor`) still need `paint()` because `ctx.fillStyle` reads at draw time.

6. **Font-changing reflow awaits `document.fonts.load` first.** When the patch is in the `'reflow'` bucket, before calling `measureCellSize`, await `document.fonts.load(\`${theme.wireframeFontSize}px ${theme.wireframeFontFamily}\`)` and `document.fonts.load(theme.proseFontMeasure)`. Otherwise we measure the system fallback font (the current race is masked by `ensureProseFontReady` being awaited once on mount but never re-awaited on font changes). The await blocks the reflow promise; subscribers fire only after metrics are correct.

7. **Canvas sizing — no work needed.** Verified in v3 review: `DemoV2.tsx:413` sizes `canvas.width`/`canvas.height` to viewport×DPR (intentional, to stay under GPU texture limits), while content growth is handled by `contentH` driving `[data-spacer]` height (`:407–408`) for native scrolling. The canvas just translates its rendering offset on scroll. Increasing font sizes makes `contentH` grow, the spacer grows, scrollbars adjust — the canvas backing buffer stays viewport-sized and correct. **Drop this step. Do not touch canvas sizing logic.**

8. **`ThemePanel` binds to React via `useSyncExternalStore`.** The panel can't read `theme.foo` directly in render — React wouldn't know to re-render on `updateTheme`. Pattern: `theme.ts` exports `subscribe(listener)` and `getSnapshot() => frozenSnapshot`; the panel calls `const t = useSyncExternalStore(subscribe, getSnapshot)` and renders from `t`. Implementation: keep a module-level `let _snapshot = Object.freeze({...theme})` that's regenerated synchronously inside `updateTheme` (after `Object.assign` but before `notifySubscribers`); `getSnapshot` returns `_snapshot` directly so back-to-back calls during a single React render return the same reference (required by `useSyncExternalStore`'s tearing-detection contract — returning a fresh object every call causes infinite re-renders). On `updateTheme`, `_snapshot` becomes a new frozen reference, subscribers fire synchronously, React's `Object.is` check detects the change and re-renders all panel controls. This handles the Reset button case Gemini flagged in v1.

9. **The popover is a separate component** at `src/ThemePanel.tsx`, mounted unconditionally inside `DemoV2.tsx` next to the existing toolbar div (around `DemoV2.tsx:1517`). Visibility is controlled by `themePanelOpen` state in `DemoV2.tsx`; default closed. Toggle via toolbar gear button (sits next to existing `Bands`/`Wrappers` toggles) and `Cmd+,` keyboard shortcut (added to existing keyboard handler). Panel layout: vertical stack, four sections — `Prose` (font family combobox, size 8–32, line height 12–48, color picker), `Wireframe` (monospace-only font combobox, size 8–32, color picker), `Layout` (`charWidthMultiplier` slider 0.8–1.5 step 0.01, `charHeightMultiplier` slider 1.0–2.0 step 0.01), `Color` (bg, prose-fg, wireframe-fg, selection, grid/border). Reset button at bottom calls `resetTheme()`.

10. **Theme subscription lives in its own `useEffect` in `DemoV2.tsx`.** Not bundled with the keyboard-listener effect (Gemini flagged this — coupling unrelated lifecycles causes churn). One effect: `useEffect(() => theme.subscribe(handle), [])` where `handle(kind)` switches on `'reflow'`/`'paint'`/`'css-vars-only'` and dispatches accordingly. The effect returns the unsubscribe.

11. **Sliders debounce *reflow*, never the React notification, color pickers don't debounce at all.** Per step 1's ordering rule, `updateTheme`'s synchronous half (mutate + snapshot + notify) always runs immediately so the controlled input's `value` prop tracks the drag. The debounce wraps the *side-effect dispatch only* — a 100ms trailing-edge debounce on the reflow handler in `DemoV2.tsx`'s subscription effect, keyed per bucket, so dragging the multiplier slider at 60fps fires one reflow at the end of the drag instead of 60. Implementation note: the panel calls `updateTheme(patch)` on every `onChange` event with no debounce; the debounce lives inside the subscriber that does the reflow work, not in the panel. Font-size number inputs commit on blur or Enter (no debounce — stepping is one click). Color pickers fire on every change because color updates are paint-only or CSS-var-only and cheap.

12. **Persistence via `tauri-plugin-store` with capability declaration.** Add `tauri-plugin-store = "2"` to `Cargo.toml`, register in `src-tauri/src/lib.rs` setup via `.plugin(tauri_plugin_store::Builder::new().build())` (corrected from `Builder::default()` per Gemini — the v2 API uses `new()`). **Tauri v2 is default-deny IPC**: must add `"store:default"` to the permissions array in `src-tauri/capabilities/default.json`, otherwise the frontend's store calls fail with permission errors. From the frontend, `theme.ts` imports `Store` from `@tauri-apps/plugin-store` (add the `@tauri-apps/plugin-store` npm dep), opens `theme.json` lazily on first `updateTheme` call, writes the full theme after every change (debounced 500ms — disk writes shouldn't fire mid-drag). On startup, `DemoV2.tsx`'s init effect awaits `loadTheme()` *before* `measureCellSize()` (otherwise we'd measure with defaults then re-measure with persisted values — wasted work and a visible flicker).

13. **Default theme matches today's hardcoded values exactly.** `proseFontFamily: 'Inter'`, `proseFontSize: 16`, `proseLineHeight: 22` (matches `textFont.ts:14`), `proseColor: '#e0e0e0'`, `wireframeFontFamily: 'Menlo, Monaco, "Courier New", monospace'`, `wireframeFontSize: 16`, `wireframeColor: '#e0e0e0'`, `charWidthMultiplier: 1.0`, `charHeightMultiplier: 1.4`, `bgColor: '#1e1e2e'` (canvas bg from `DemoV2.tsx:36`), `selectionColor: '#4a90e2'`, `gridBorderColor: '#444'` (matches `DemoV2.tsx:1523` divider). Zero visual change at first launch with no `theme.json` present.

14. **Selection-color phase 1 covers toolbar only.** `DemoV2.tsx:1519` hardcodes `#4a90e2` for the active tool button background. `selectionColor` covers this. Wireframe selection stroke in `frameRenderer.ts`'s `renderFrameSelection` stays untouched this round — called out under "what does NOT change" so the boundary is clear.

15. **Tests: vitest unit + manual smoke.** `src/theme.test.ts` verifies: `updateTheme` classifies patches correctly (`bgColor` → `'css-vars-only'`, `proseColor` → `'paint'`, `wireframeFontSize` → `'reflow'`, mixed patch → strongest), `theme` object reflects mutations, `resetTheme` restores defaults, `subscribe`/`unsubscribe` works, `getSnapshot` returns a new reference per update. No test for the panel UI or the persistence round-trip — those are smoke-tested manually after plumbing lands. Existing 372 vitest + 125 harness e2e must still pass with default theme; a regression there means the const→theme migration broke a call site.

16. **Edge case: monospace font picker on machines without listed fonts.** Combobox lists `Menlo, Monaco, Courier New, SF Mono, JetBrains Mono`, but only the first three ship on every macOS. Picker entries pre-filtered using `document.fonts.check('16px <name>')` on mount — missing fonts hidden. Caveat (per Gemini): `fonts.check()` returns false for unloaded web fonts; if web fonts are added later, this filter needs to call `fonts.load` first. Not a current-scope issue. Default fallback if the persisted font is missing: revert to `Menlo` and clear the persisted value.

17. **Edge case: invalid persisted theme.** `loadTheme` runs each loaded field through a per-field validator (font sizes 8–32, multipliers 0.5–3.0, colors match `/^#[0-9a-f]{3,8}$/i`); invalid fields fall back to defaults individually rather than discarding the whole file. A partial theme (user only customized colors and the schema gained new fields later) loads cleanly.

## What does NOT change

- **Frame model and grid coordinates.** Theme affects pixel derivation only; `gridRow`/`gridCol`/`gridW`/`gridH` are untouched. `gridSerialize.ts` doesn't read theme.
- **Wireframe selection stroke** in `frameRenderer.ts`'s `renderFrameSelection` — stays at its current hardcoded color this round. `selectionColor` only covers the toolbar active-button background in phase 1.
- **`UnsavedChangesModal.tsx` button colors** — modal styling is separate concern.
- **The scanner, reflow, autoLayout, gridSerialize.** None of these read display constants; they operate in grid units.
- **Existing e2e artifacts.** Tests run with default theme; pixel-comparison would break if defaults shifted, so defaults are pinned to current values.
- **Existing Tauri commands.** No new Rust commands — store plugin handles persistence directly from TS.
